## 🃏 Cards

### 🧱 Architecture — 5/5

The tag graph was already real: every project's `nx.tags` matches
[`boundaries.ts`](../../packages/configs/src/eslint/lib/boundaries.ts) and the
[root README's table](../../README.md#-architecture--boundaries) verbatim, the rule is registered as
`"error"` rather than warn, `content` and `i18n` each cut a genuine port/adapter seam with a lazy
registry so a new vendor is a map entry rather than a change to any caller, and `apps/huella-legal`
composes leaves only through their published `exports`. What held the card at 4 was that the
invariant underneath all of it — `core/` never importing the Nuxt or Nitro runtime — lived only in
two `CLAUDE.md` files. Tag boundaries cannot reach it, because `@nx/enforce-module-boundaries`
reasons about project-to-project edges and never about subpaths inside one project, and the runtime
deps are already present as devDependencies and optional peers, so a stray import compiled,
typechecked and shipped.

That is now [`coreIsolation.ts`](../../packages/configs/src/eslint/lib/coreIsolation.ts): a
`no-restricted-imports` rule scoped to `**/src/core/**`, composed into both the node and vue
factories, and therefore running in the pre-push hook and in CI. The breakage was attempted rather
than assumed — adding `import { defineEventHandler } from "h3"` to
`packages/content/src/core/registry.ts` fails `nx lint @monorepo/content` with the rule's own
message naming the port to use instead.

| Costs a point | Evidence |
| --- | --- |
| Nothing — the sweep found no remaining gap | Tag tables agree; the rule is `error`, not warn; no package reaches a vendor SDK, env var or transport outside its adapter (`process.env` — one hit, in `type:infra`); `content` and `i18n` diverge only where their ports genuinely do |

### 🧩 Implementation — 4/5

Zero `any`, zero `@ts-ignore`/`@ts-expect-error`, zero `eslint-disable` across the tree, and that one
is enforced rather than merely observed: `no-explicit-any` is an error through the
`recommendedTypeChecked` set pulled in by
[`packages/configs/src/eslint/node.ts`](../../packages/configs/src/eslint/node.ts), and that lint run
is both the pre-push hook and CI. Error paths are honest everywhere. Both `OfetchHttpClient`s rethrow
as a typed `UpstreamError`; the BFF routes pass a domain error through untouched and re-wrap only a
genuinely unknown cause; the translations controller separates a missing file (404) from a read or
parse failure (500) instead of collapsing both. Malformed vendor payloads are handled rather than
trusted — WordPress's `x-wp-total` is guarded against a proxy dropping it, and Tolgee's response is
checked for the requested locale before use.

| Costs a point | Evidence |

| A byte-identical `toWordChars` lives in two packages that cannot share code, with nothing pinning them together | [`packages/content/src/core/contentKey.ts:9-11`](../../packages/content/src/core/contentKey.ts#L9-L11) vs [`packages/i18n/src/core/translationsKey.ts:15-17`](../../packages/i18n/src/core/translationsKey.ts#L15-L17) — the boundary forces the copy, but fixing one silently leaves two cache-key schemes, and the tradeoff still isn't written down in either `CLAUDE.md` |

Swept and found clean: type and lint escapes, error paths returning a success-shaped value, and
duplicated business logic beyond the two-line utility above.

### ⚙️ Tooling & DX — 4/5

The two gaps that capped this at 3 are closed. `lint` and `typecheck` now declare
`["default", "^production"]` in [`nx.json:19-28`](../../nx.json#L19-L28), matching what `test`
already had, and the effect was verified rather than assumed: `nx lint @monorepo/content` reported
`existing outputs match the cache`, then re-ran after a rule was edited in `@monorepo/configs`. A
rule change there now enters every consumer's hash, which is what makes the whole shared-config
design safe, and the manual "run `run-many` by hand" instruction that stood in for it has been
replaced by a note not to remove the inputs. The fresh-clone step is also documented now:
`git config core.hooksPath .husky` sits in the root README's getting-started block with the reason
beside it — husky cannot self-install because lifecycle scripts are banned and CI installs with
`--ignore-scripts`.

What keeps it off a 5 is parity. The pre-push hook runs `lint`, `test` and `typecheck` on affected
projects; CI runs those **plus `build`**, and `apps/huella-legal` typechecks on build, which is where
most failures actually surface. A green push is still not a green pipeline. The gap is named in two
places, which is precisely the anchor-4 test — deliberate and written down — rather than the
anchor-5 one.

| Costs a point | Evidence |
| --- | --- |
| `build` runs only in CI, so the local gate can pass on a tree that fails the pipeline | [`.husky/pre-push`](../../.husky/pre-push) against [`ci.yml`](../../.github/workflows/ci.yml); documented at [`CLAUDE.md:66-68`](../../CLAUDE.md#L66-L68) and [`README.md`](../../README.md#-git-conventions), which is what keeps it from capping the card lower |

Swept and found clean: no target fails on this tree, and every cached target's declared outputs match
what its tool writes.
