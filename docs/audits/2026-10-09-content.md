# 🔎 Content: readiness for a second WordPress app

## 🗺 Context

A static read of `packages/content`, covering every non-spec file under `src/`. It also covers the
one consumer, `apps/huella-legal/layers/articles`, where the package's shape shows up as app code.
The question is whether the package works as a plug-and-play WordPress reader for the next app
rather than for Huella only. [`0031`](../decisions/0031-content-server-accessor.md) settled the
topology (one cached server `useContent(event)`, no public route), and this audit takes it as
given: the findings are about the domain model and the cache contract.

A finding marked **Confirmed** was reproduced by feeding a hand-built WordPress post to `toEntry`
from a scratch spec (B1, Q2), or by grepping the tree (D1). **Likely** means reasoned from the code
and not reproduced. Line numbers are from the working tree at `commit`, which differs only by
deleted comments in `useContent.ts`.

Several findings are rows in the package README's
[deferred table](../../packages/content/README.md#-deliberately-deferred). They are filed here
because "more WordPress apps soon" is the trigger those rows were waiting for.

## 🪜 Order

1. **Q1, Q2 and Q3 first, together.** They decide whether a second WordPress app can plug in
   without editing the package, and they share one config shape.
2. **B1 with D2.** Decoding moves into the provider and the app's copy is deleted in the same
   change.
3. **Q4, which closes D1 for free.**
4. **Q6, which also settles B2** if the purge clears both key families. Q5 belongs in the same
   change, since both touch the module options.
5. Q7–Q10 are independent and can go in any order.
