# 🔎 Scripts: bugs, duplication and weak code

## 🗺 Context

A static read of `infrastructure/scripts`, covering every non-spec file under `src/`. A finding
marked **Confirmed** was reproduced by calling the module itself from a scratch script (B4, B5, B6),
or by grepping the committed file it describes (Q1). **Likely** means reasoned from the code and not
reproduced. The rest were read only. Line numbers are as of `commit`.

[`0019`](../decisions/0019-scripts-quality-audit.md) was the previous pass over this package, and
anything it settled is left out here. Two examples: the `titleCase` merge has landed, and the two
`currentBranch` adapters stay separate by that report's decision.

1. **B3, B1 and B2 first.** They're the user-visible ones. B3 throws away a typed issue, B1
   silently breaks offline `issue:pick`, and B2 makes drift stop asking. Each needs a spec that
   pins the failure (`writing-tests`).
2. **D5 before B1**, so the empty-list guard lives in the one cache write.
3. **D3 before B5.** Both change `FEATURES.md`. Land the walker merge, confirm `pnpm docs:map
   --check` is unchanged, then apply B5 and review its re-render on its own. The merge fixes Q5
   for free.
4. **B4, B6, B7, B8 and B9** are independent small fixes. B4 and B9 only matter once Q1 puts drift
   back in a hook, so settle Q1 alongside them.
5. **The remaining D and Q rows** in any order. D1, D2, D4, D6 and D7 are behaviour-neutral, and
   the existing specs should pass untouched.
